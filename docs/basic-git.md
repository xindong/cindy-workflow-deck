# 基础 Git 与项目门禁

Cindy 面板默认显示基础界面，高级界面保留五个工作流。独立桌面使用同一 Git 页面和服务，不依赖 AI；独立端高级工作流及 AI 诊断尚未实现。

## 操作

- 状态、工作区/暂存区差异、最近20条提交、本地分支列表。
- 创建并切换分支；干净工作区切换已有分支。
- 暂存/取消暂存勾选文件；提交现有暂存内容，不自动添加其它文件。
- 获取 origin、仅快进拉取、推送当前工作分支，不提供强推、重置、清理、自动stash或跳过hooks。
- 使用本机已安装并登录的 gh 创建PR；发现项目PR模板时预填描述，不自动合并。

## 门禁

工具保守保护 main、master 和本地 origin/HEAD 所指默认分支，禁止直接提交和推送，引导“新建分支→暂存→提交→推送→PR”。这不是实时远端保护查询；远端额外策略仍由服务器执行，项目其它分支约定仍须遵守。

只读展示根AGENTS.md、CONTRIBUTING.md、跟踪的嵌套AGENTS、项目内Markdown引用路由和PR模板。最多80份候选、每份128KB、总正文256KB；读取不完整则阻塞写操作。不读取外部链接或符号链接目标。

检查实际core.hooksPath和hook可执行性；项目有.githooks但未启用，或存在不可执行hook时阻塞写操作。原生提交/推送完整保留项目hooks和LFS检查，不替用户修改配置。识别DCO约定时附加signoff，识别Conventional Commits约定时检查基本标题格式。

这些检查不等于任意自然语言规则均已自动验证。文档中未被hooks覆盖的测试、审批、锁定与业务条件，用户须实际完成后确认；不能判断时不要确认，应到高级工作流核对。界面不会显示“全部项目规则自动通过”。高级任务同样要求读取项目规则，不得跳过hooks或向主分支直接提交。

每次写入使用十分钟内的一次性确认，绑定根目录、分支、HEAD、暂存内容、工作区状态、规则正文及hook摘要。执行前重查，发生变化则拒绝；同仓串行执行，票据在执行前消耗，进程退出或超时后不自动重放。失败可能部分成功，先刷新核对实际状态。

## 环境与验收

使用本机Git；Windows同级存在git/bin/git.exe便携包时优先使用。固定操作使用参数数组并清除外部GIT环境覆盖，不开放任意shell；Git自身hooks、过滤器和认证按项目执行。PR还需本机gh及远端权限。

node --test tests/git-service.test.mjs 验证真实临时仓库、bare远端、hook拒绝和过期/重复请求。node tests/git-ui-check.mjs 验证真实Electron分支/暂存/提交、DCO、主分支门禁，以及模拟Cindy宿主的基础/高级切换、Git RPC和320/860px明暗布局。

不在业务项目执行Git写入，不创建真实远端PR。插件安装、用户设备操作和远端PR需另行验收。
