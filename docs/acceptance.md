# 首版验收

## 已确认设计

- 名称：Cindy Workflow Deck；插件 ID：`workflow-deck`。
- 源码目录：`/Users/yuanzhengjie/Documents/cindy_plugin/cindy-workflow-deck`。
- 私有仓库：`https://github.com/xindong/cindy-workflow-deck`。
- 形态：左侧停靠面板，原生独立窗口、最小化、撑满全部开启。
- 五个按钮每次新建独立任务；没有跨任务聊天继承。
- 任务项目、模型和权限交给 Cindy 原生任务设置，不另造配置系统。
- 通过稳定 UUID + Host 持久 requestKey 去重；创建前、派发前保存日志，自动传输重发只读已有记录，业务恢复必须由用户明确点击。

## 自动化检查

`node --test tests/*.test.mjs` 覆盖五个指令映射、独立任务、重复包、跨重启去重、创建回执丢失、派发回执丢失、权限拒绝、能力缺失、存储失败、无效回执、真实状态读取和 64KB 日志容量边界。

`node scripts/check.mjs` 检查清单引用文件、语言资源、CSP 内联脚本禁用和 JS 语法。

`tests/serve-preview.py` 是仅本机测试夹具，提供模拟 Host API 和主题注入，用于浏览器验证，不随插件打包。它不调用真实 Agent，不创建真实任务。

## Cindy 实机验收清单

以下项目必须在安装后实测，不可用单元测试或打包成功替代：

- [ ] 权限卡只展示普通任务能力；可拒绝，拒绝后不循环弹窗。
- [ ] 启用后五个按钮与任务单逐字对应。
- [ ] 设置项目目录和模型，点击按钮后新任务出现在任务列表，工作目录正确。
- [ ] 连续两次独立点击得到两条不同任务，五个按钮各自的初始指令正确。
- [ ] 源项目流程文件 / Skill 不存在时，Agent 明确报告，不编造流程。
- [ ] 分离为 OS 窗口、最小化再恢复，界面可继续操作。
- [ ] 切换 Light / Dark，控件与滚动条跟随 Host。
- [ ] 面板关闭、独立窗口重开或 Cindy 重启后，已有记录仍可读。
- [ ] 断线 / 回执丢失后核对原请求，不重复创建任务。
- [ ] 最终 PR / 分支操作在安全测试仓完成；不在业务仓盲测破坏性流程。

未实际完成的项保持未勾选。
